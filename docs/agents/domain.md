# Domain documents

This is a single-context project. Read the root `CONTEXT.md` for domain terms before planning
or changing gateway behaviour. Read relevant decisions under `docs/adr/` if that directory exists.
Missing ADRs do not block work. Create ADRs only for consequential decisions that need their rationale retained.

Keep `CONTEXT.md` a glossary. Put behaviour, acceptance criteria and implementation choices
in the feature spec. Use glossary terms in specs, tickets, interfaces and tests.
